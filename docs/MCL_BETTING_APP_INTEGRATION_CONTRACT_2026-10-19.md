## MCL sporting contract
Default Season 1: 24 numbered marbles in 6 color families, 4 per family. Operator may configure compatible roster size in multiples of 6, with balanced family counts, and preview/draw a complete schedule before publication. 10 matchdays, 4 races/matchday for the 24-marble default, all races precisely 6 marbles, each marble once/matchday, 6/5/4/3/2/1 standings points. Published draw and starting lanes immutable after relevant market opens (unless host voids/refunds and republishes). End regular season top 12, seeded two six-marble playoff races (top 3 each), then one six-marble final. A regular-season last place is NOT a championship elimination. Use published tie breakers and a proper tie-resolution procedure; host confirms complete unique 1st–6th order.
Preseason champion selections only, multiple distinct marbles/player allowed, x8 maximum FUNDED indicative return, per-ticket early entry weighting only if published prior to season. Race winner up to x2, exact place up to x3, separate pools. Maxima are not guaranteed accepted locked multipliers. If the live target uses immutable bookmaker odds, DO NOT silently mix those semantics with a dynamic prize pool: a separately approved and funded product rule is needed. Do not expose other players' stakes/tickets, aggregate pool totals or operator exposures to player routes/client bundles.
Default initial split to model: 60% operator virtual allocation and 40% prize allocation PER isolated market. Every accepted payout and cash-out must fit in that market's funded prize balance, with integer rounding/remainder accounting. Unclaimed prize allocation does not automatically roll over and its published destination is audited. Candidate cancellation policy: before championship exposure and before a market lock, early cancellation returns 90% virtual stake and audits 10%; after start, only an optional SEPARATELY FUNDED virtual ticket buyout can settle early. All stakes, weights, voids and buyouts require an immutable ledger and idempotent settlement.
Operator may prepare current season and two future seasons; future championship entry windows are independent. 2026-10-20 13:00 Asia/Manila = 05:00 UTC is EXAMPLE opening schedule only, NOT automatically a live launch. Persist timezone and absolute UTC deadlines; at/after scheduled race lock, reject new entries, cancellations and virtual buyouts server-side even if operator is offline, and host can lock early. Host can publish YouTube/Facebook livestream link; link does not determine settlement. Only validated, operator-confirmed physical finishing order performs atomic result, points, market and wallet settlement once. Re-entrant or duplicate confirmation must not pay twice; explicit host correction/void protocol required.

## Required adapter boundaries (design, not assumptions about target app)
- getAuthenticatedPlayer() and requireHost() use target secure server identity; never trust localStorage, hidden tabs or request-supplied player IDs.
- availableVirtualBalance(playerId) from target wallet's authoritative available balance, not vault/future earnings.
- transactionalLedgerMutation({playerId, amount, reason, idempotencyKey, marketId, ticketId}) uses target atomic ledger API; no second writable coin balance.
- mcl_store: seasons / participant marbles / schedule / result version / market state / accepted ticket / pool allocations / championship shares / eliminated-state / private cashout quotes / operator audit; enforce account RLS and host-only writes.
- serverNow() and server transaction adjudicate lock and stale quoted state; never trust browser clock.
- result settlement routine has unique race result version and market+ticket idempotency, snapshots risk exposure, applies operator/prize allocation and reopens only eligible markets. All-or-nothing database transaction.
- player views show own wallet/tickets, current offered estimates, standings, broadcast URL; not any opponent private prediction or totals.
- host can add/deduct arbitrary approved virtual amounts with reason, actor/time, no negative available balances and no modification of previously accepted tickets.
